# مجموعه ارزیابی کوچک فارسی (پیش‌نویس)

این مجموعه برای سنجش دو چیز نوشته شده: **دقت** (وفاداری به متن مبدأ) و **روانی** (طبیعی بودن فارسی). این دو امتیاز جدا گزارش می‌شوند، نه یک عدد واحد.

## فایل‌ها

- `samples.jsonl`: هر خط یک نمونه با متن انگلیسی، ترجمه‌ی تحت‌اللفظی و ترجمه‌ی طبیعی.

## ساختار هر نمونه

| فیلد | معنا |
|---|---|
| `id` | شناسه‌ی یکتا |
| `genre` | ژانر: `chat`، `dialogue`، `narrative`، `poetry`، `subtitles`، `technical`، `ui`، `scientific`، `medical`، `legal`، `news`، `financial`، `philosophy`، `classical`، `transcreation`، `edit`، `mystery`، `speculative` |
| `source` | متن انگلیسی |
| `literal` | نمونه‌ی ترجمه‌نمایی برای سنجش؛ عمداً حاوی خطای شناخته‌شده |
| `natural` | ترجمه‌ی طبیعی پیشنهادی؛ هنوز توسط گویشور بومی بازبینی نشده |
| `calques` | الگوهای ترجمه‌نمایی موجود در `literal` |

## روش استفاده

1. به یک داور (LLM یا بازبین انسانی) `source` و یک ترجمه‌ی ناشناس بدهید.
2. داور دو امتیاز ۱ تا ۵ بدهد: **دقت** و **روانی**.
3. داور الگوهای ترجمه‌نمایی را علامت بزند. نسبت جمله‌های علامت‌خورده گزارش شود.
4. نتیجه را روی صفحه‌ی دو‌بعدی (دقت، روانی) رسم کنید، نه فقط میانگین.

## محدودیت‌ها

- این مجموعه ۸۸ نمونه دارد (۶۲ مثبت، ۲۶ منفی) و هنوز برای سنجش آماری کافی نیست. نمونه‌های `real-*` از متن‌های واقعی آمده‌اند: متن‌های `docs/research/real-texts/` و متن‌های مالکیت عمومی (داروین، فارادی، آدام اسمیت، هیوم، دکارت، گیبون، ایلیاد، سفر پیدایش، آستن، کانن دویل). منبع هر نمونه در فیلد `note` است.
- نمونه‌های `natural` را یک مدل نوشته‌اند. قبل از هر ادعای کیفیت باید گویشور بومی بازبینی کند.
- داوری LLM ممکن است به متن خودش امتیاز بیشتری بدهد. برای نتیجه‌ی جدی، بازبین انسانی لازم است.

## اجرای خودکار

```bash
# سنجش خود ابزار: نمونه‌های منفی نباید تغییر کنند یا هشدار بگیرند،
# و نسخه‌ی تحت‌اللفظی باید بیشتر از نسخه‌ی طبیعی هشدار بگیرد.
python benchmarks/eval_naturalness.py

# امتیاز سبکی یک خروجی: هر خط {"id": ..., "translation": ...}
python benchmarks/eval_naturalness.py --candidates out.jsonl

# پرامپت داور (دقت و روانی، جدا از هم) برای یک نمونه
python benchmarks/eval_naturalness.py --judge-prompt dlg-01
```

امتیاز خودکار فقط شمارش هشدارهای لینتر است و جای داور را نمی‌گیرد. برای مقایسه‌ی جدی دو نسخه از مهارت، از پرامپت داور یا بازبین انسانی استفاده کن.

در CI، اگر نمونه‌ی منفی‌ای به دست اصلاح خودکار تغییر کند، اجرا شکست می‌خورد.

## آخرین اندازه‌گیری (۲۰۲۶-۱۱-۰۸)

۳۳ نمونه‌ی تازه اضافه شد: ۲۳ مثبت در ژانرهایی که پیش‌تر نمونه نداشتند یا کم داشتند (علمی، مالی، فلسفه، کهن و مذهبی، تبلیغاتی، رابط کاربری، چت، زیرنویس، پزشکی، ویرایش) و ۱۰ منفی (فارسی درست در همین سبک‌ها که نباید هشدار بگیرد).

| | پیش از اصلاح لینتر | پس از اصلاح |
|---|---|---|
| تشخیص نسخه‌ی تحت‌اللفظی (کل) | ۳۰ از ۵۸ | ۴۱ از ۵۸ |
| تشخیص در ۲۳ نمونه‌ی تازه | ۷ از ۲۳ | ۱۸ از ۲۳ |
| با نشانه‌های نگارشی (خط تیره، گیومه، ممیز) | | ۴۵ از ۵۸ |
| هشدار روی نسخه‌ی طبیعی یا نمونه‌ی منفی | ۰ | ۰ |
| هشدار تازه روی ۳۷۹ جمله‌ی «فارسی خوب» جدول‌های راهنما | | ۰ |

۱۵ الگوی تازه به `LINT_CALQUE_PATTERNS` اضافه شد («آیا شما»، «این جالب است که»، «وجود ندارد که»، «مورد نیاز نیست»، «بالا باقی می‌ماند»، سه «یک» در یک جمله، «به ... خداحافظی کنید» و ...).

**آنچه لینتر نمی‌بیند:** خطای انتخاب واژه و لحن. نمونه‌های فلسفه («office ← دفتر»)، کهن («آواز بخوان»، «دوران مسیحی»)، حقوقی («deal ← معامله») و طنز آستن الگوی سطحی ندارند. این‌ها را فقط بازخوانی روانی (گام ۴ مهارت) و داور می‌گیرند. برای همین در `tests/test_eval_set.py` آستانه «بدتر نشدن» است، نه «همه».

بعداً چهار نمونه برای دو راهنمای تازه اضافه شد (`mys-*` و `spec-*`): تشخیص کل ۴۲ از ۶۲ و با نشانه‌های نگارشی ۴۶ از ۶۲؛ هشدار روی نسخه‌ی طبیعی همچنان ۰.
